# Техническое задание на разработку HON-platform

## Регистрация и авторизация пользователей

### Регистрация по email

В приложении следует предусмотреть возможность регистрации пользователей классическим способом:
- на странице регистрации пользователь вводит свой email и пароль;
- пользователю отправляется на почту ссылка для подтверждения аккаунта;
- после того, как пользователь переходит по ссылке - регистрация считается завершенной, пользователя перенаправляют на платформу;
- пользователь заполняет в профиле данные о себе.

Следует предполагать, что в системе есть возможность авторизации через аккаунт Яндекса. Поэтому нужно учесть, что если почта пользователя принадлежит сервису Яндекса, то необходимо пользователю давать возможность входит в этот же аккаунт не по паролю, а через YandexID. То есть автоматически связывать аккаунты у которых указана почта Яндекса вне зависимости от способа входа. Если пользователь ввёл данные от другой почты, то вход по YandexID в этот же аккаунт будет не возможен.

При помощи конфига или .env переменных должна быть возможность указания данных для управления сервисной почтой владельца сервера внутри приложения. Это необходимо для того, чтобы при регистрации по почте пользователю было автоматически отправлено сообщение на его почту для активации аккаунта.

### Регистрация по YandexID

В приложении следует предусмотреть возможность регистрации пользователя с помощью аккаунта Яндекс пользователя:
- пользователь видит сообщение, что он может войти в систему с помощью его Яндекс аккаунта и жмёт на кнопку соответствующую;
- система регистрирует пользователя по его YandexID при этом предполагается, что у пользователя не заполнены логин с паролем в системе;
- почта должна быть автоматически заполнена из данных по YandexID пользователя. Предполагается, что почта у аккаунта будет заполнена автоматически, но пароль у аккаунта не будет задан
- пользователь заполняет в профиле данные о себе.

В настройках профиля в приложении должна быть возможность установки пароля для аккаунта. Это необходимо для того, чтобы пользователь мог установить пароль для входа при помощи логина и пароля, так как следует предполагать, что почта от YandexID может использоваться для входа в качестве логина. 

Также этот же функционал будет использоваться для смены пароля в аккаунте. 

### Авторизация по логину и паролю

Классический вход в аккаунт через логин с паролем.

### Авторизация по YandexID

Если пользователь входит через YandexID, которая уже зарегистрирована в системе, то вместо процесса регистрации запускается авторизация. 

### Авторизация по QR коду

Необходимо предоставить возможность входа в аккаунт путём сканирования QR кода. Если пользователь авторизован в мобильном приложении платформы, то он может использовать функционал сканирования QR кода, который показывается на странице авторизации в браузере. После сканирования он должен дать подтверждение на авторизацию в его аккаунте. 

### Функционал сброса пароля

Следует предусмотреть возможность установки нового пароля на случай, если пользователь забыл свой пароль.

Порядок сброса пароля:
- пользователь на странице авторизации указывает свою почту;
- рядом с полем ввода пароля должна быть кнопка сброса пароля;
- после нажатия на кнопку сброса пароля пользователю на почту, которая была заполнена в форме отправляется ссылка для его сброса;
- после того, как пользователь переходит по ссылке - его перенаправляет на страницу сброса пароля;
- пользователь вводит новый пароль и повторяет его;
- после этого его перенаправляет на главную страницу приложения, пароль теперь измененный.

## Лента социальной сети

При входе в HON-platform пользователь попадает на страницу с лентой. Она представляет собой способ просмотра постов. 

## Принцип формирования ленты

Лента будет формироваться на основе двух механизмов:
- подписок пользователя: посты других пользователей и сообществ, на которых подписан человек;
- рекомендательная система постов других сообществ / пользователей.

Формирование ленты на основе подписок будет представлено простым способом - отображение постов в хронологическом порядке в зависимости от их публикаций. Посты из подписок будут перемешены с постами из рекомендаций в виде единой ленты.

Так как HON-platform - это небольшой инди-проект, то может быть недостаточно ресурсов для построения продвинутой рекомендательной системы, поэтому она будет упрощенной. Для каждого пользователя будет составлен перечень сообществ и других пользователей, которых он встречал в ленте. Для каждого из них будет заполняться рейтинг заинтересованности пользователя.

## Рейтинг заинтересованности пользователя

Изначально для всех сообществ и других пользователей будет задан единый рейтинг заинтересованности, который может расти или снижаться от исходного значения. Его значение будет влиять на то, как часто посты данного сообщества будут показываться в рекомендациях. Так как рейтинг для всех сообществ и пользователей единый, то изначально рекомендации будут браться случайным образом.

Будут несколько механизмов, влияющих на изменение рейтинга заинтересованности:

### 1. Вычисление времени удержания пользователя при просмотре поста 

Для каждой публикации вычисляется время удержания пользователя, что позволяет судить, дочитал ли он пост до конца или пролистал. Для этого рассчитывается среднее время удержания пользователей на конкретном посте, после чего время данного пользователя сравнивается с этой средней величиной. Факт пропуска или задержки влияет на рост или снижение рейтинга.

### 2. Выставление позитивной реакции на пост

Если пользователь оставил у поста позитивный эмодзи, то это влияет на рейтинг заинтересованности и повышает его для данной подписки у пользователя. 

При этом аналогичный механизм для негативных реакций и комментариев делать не нужно. Негативные реакции могут оценивать контент внутри поста, например, могут отображать реакцию пользователя на новостное событие. Комментарии могут быть как негативными, так и позитивными. Поэтому как для комментариев, так и для негативных реакций нельзя однозначно говорить о том должен ли рейтинг заинтересованности вырасти или понизиться. Но для такого случая продолжает работать оценка рейтинга на основе удержания пользователя на публикации.

### 3. Явная реакция пользователя через меню действий

У поста будет расположена кнопка для открытия меню действий. Нажатие на неё будет открывать всплывающее меню со списком. Часть из действий будет влиять на рейтинг заинтересованности пользователя по отношению к пользователю или сообществу, опубликовавшему пост.

Действия, влияющие на рейтинг заинтересованности:
- Скрыть посты этого сообщества / пользователя - обнуляет рейтинг заинтересованности пользователя для данного сообщества / пользователя и выставляет блокировку на отображение его публикаций в ленте. Посещение страницы данного сообщества / пользователя будет снимать блокировку, но рейтинг начнет расти заново (автоматически прошлое значение рейтинга не возвращается);
- Показывать меньше постов этого сообщества / пользователя - снижает рейтинг заинтересованности пользователя для данного сообщества / пользователя на определенное значение.
